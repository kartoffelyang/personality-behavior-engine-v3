# 原子能力模拟执行台

入口：在 `/fast?job=<生成记录ID>` 点击“查看请求、返回与模拟车机反馈”，或打开 `/soa-sim?job=<ID>&persona=ESTJ`。

这是基于现有57项原子能力定义编写的**本地模拟传输与状态执行器**，没有接入实车。`sim.climate / 温度调节` 等名称是本项目自己的演示协议，不是厂商SOA方法。没有HTTP车端请求、SOME/IP或DDS报文，也不会播放音频、发送消息或支付。

## 与原策略页面的区别

- 用户逐步执行计划，模拟服务消费实际参数，返回结构化响应。
- 必需参数缺失时不发出调用；查询结果通过会话上下文传给后续步骤。候选ID必须来自前序查询。
- 播放、温度等动作更新模拟车机状态；搜索不等于已播放，计划不等于已完成。
- 音乐候选页的“选择并模拟播放”是明确的用户手动追加操作，单独记为内容选择、播放控制两次调用，不冒充模型生成步骤或人格效应。
- 每条日志含request、response、状态差异、本地耗时及来源。`dispatched=false`表示参数在适配层被拒绝；`true`表示进入本地模拟服务，并不表示发往实车。
- 故障注入会返回SIMULATED_TIMEOUT/REJECTION，保持车况与上下文不变且不推进游标。预期revision防止重复点击执行。
- ESTJ/INFP会话使用相同初始演示车况并分别保存，重置会创建新会话。数据位于`output/soa_sim/`。

## 演示数据与限制

初始温度26℃、风量1、音量15、演示时钟09:25，以及内容、地点、路线、餐饮列表均为固定演示数据，与用户当前车辆、位置和个人记录无关。模拟器参数范围仅是本项目的演示约束。缺少历史时恢复/历史读取返回NO_SAVED_STATE；不补造个人历史。

当前执行器没有对自然语言策略做二次LLM决策。计划仅有措辞区别而动作与参数相同时，会落为相同调用；不会把这种区别虚构成不同车机反馈。服务筛选等查询回显固定候选与条件，未连接真实商户或内容供应商。

接入实车仍需厂商服务字典、参数/单位/枚举、调用协议、鉴权与状态订阅、反馈码、超时和取消语义。当前UI和会话日志可以作为接入后的观察入口；不能直接声称兼容某一厂商SOA。

## 检查

`tests/test_soa_simulator.py` 覆盖搜索不播放、用户选择播放、参数缺失、确认边界、失败不变更、超时重试、revision去重、导航依赖、无历史、多个能力域与HTTP会话持久化。

## 统一行为视图

`/fast` 的结果与 `/soa-sim` 使用同一行为模块。每个动作内依次显示 ESTJ/INFP 描述与参数、保存的配置引用和解释、执行控件、返回反馈和可展开调用明细；当前状态只作为折叠快照。原首页及 comparison 保留。

差异分为服务/参数/顺序、执行方式/条件，以及描述变化。当前快速链路只将主导功能 Te 或 Fi 的 action_logic 提交给模型；完整 function_scores 和 interaction 数值不参与本链路。仅描述差异不意味着调用差异。用户手动追加的选择播放仍独立标记来源。

## 结果优先展示

打开页面会为两个独立人格会话调用 `/prepare`：仅连续执行 `auto_generate` 的公开准备步骤，在确认、选择、缺参或失败处停止。不会代用户选择、导航、播放、预约或支付。首屏展示模拟服务返回的餐厅与菜品、距离、价格、等待时间等具体候选；策略及请求明细折叠。候选相同会明确标记，并不根据人格标签强行改排序。

演示数据版本为2；旧会话记录保留，页面创建新版本会话。餐厅查询只返回餐厅类别，休息点不混入就餐候选。所有商户、菜单、距离、价格与等待时间均为固定演示数据，不是附近真实服务。故障注入移入“开发调试选项”，其含义是人为模拟超时/拒绝来验证失败处理。
