## 实际架构与缺口

1. generate_fast仅接收utterance；payload含工具目录、场景、人格因素、安全与任务契约，不含当前导航目的地、路线、日程或实时车况。compile_result的execution_context也是空context/history。
2. 一次模型调用同时生成共同方案与两个人格调整。规划校验检查字段、合法工具、权限、依赖和适用任务覆盖；它不自动获取缺失车端状态。
3. 模拟器消费静态动作及参数，维护演示状态与上下文。缺少参数会停止；确认/选择动作需要用户操作。PREPARATION仅运行无需确认的auto_generate步骤。
4. 固定服务返回不会触发模型二次规划。部分服务（例如生态筛选、比较）只回显候选和条件，没有真实筛选排序器。文本preconditions不是通用的可执行条件表达式。
5. 快速人格因素只来自主导功能action_logic：ESTJ使用Te，INFP使用Fi；完整function_scores、interaction不参与。人格是软规划提示；动作差异可覆盖是否采用、顺序、参数、模式、条件、描述，但不保证模型一定产生这些实质变化。硬性权限、依赖和任务校验由两个人格共享。
