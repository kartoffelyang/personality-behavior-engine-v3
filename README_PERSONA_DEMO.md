# 简洁人格模拟入口

访问 http://127.0.0.1:10086/demo 。原 `/comparison`、`/fast`、`/soa-sim` 保留。新入口不通过 SOA 执行器，不等待真实用户确认。

## 实际链路

共享虚拟设定与一次中立情境理解 → 原完整版 generate_behavior_plan → 人格画像、主导功能策略、场景策略、4项固定及按情境激活的交互维度 → ESTJ/INFP 两分支并行生成 → 原 validate_plan 校验 → 首屏对照。

同一分支的一次模型输出包含具体虚拟动作、最终车机话术、人格因素与决策依据。没有额外故事生成调用。新入口只用简短别名传输动作，由程序补齐显示名、序号、默认强度和共同情境标签；模型决定的工具、参数、模式、条件、具体做法、人格与决策解释均保留，仍经过完整版契约校验。编译器可在能力白名单内补齐缺失的公共查询依赖（地点搜索/详情、内容搜索、服务搜索），不会替模型选地点、内容、路线或补造授权；补齐记录写入notes。失败不换成固定人格模板。

## 使用

三个按钮读取已存实跑（存在时），明确标记“已存试跑”；“重新生成”调用大模型实时推演。自行输入情境也可生成，共同设定会补齐演示所需信息。结果只有具体回应、主要动作、一个关键差异与原因。查询机械步骤、完整原子动作、交互维度和运行记录折叠。

程序先提取是否采用不同动作，再比较非查询动作参数，最后才比较具体描述；参数键顺序不计差异，重复方法按出现次序匹配。相同结果如实保留，不将手动选择当作人格效果。

## 保存与缓存

`output/persona_demo/<job>.json` 是实际生成结果，`<job>_audit.json` 为完整链路记录，`examples.json` 为用例展示索引，`intent_cache/` 保存共享中立观察。情境缓存键含原话、虚拟世界、情境提示词及配置内容；不会缓存或预写某人格的答案。旧失败记录不覆盖。

## 实测边界

首轮下班休息完整文本输出：99.45秒。压缩输出并复用已验证的情境理解后：62.63秒，最先完成的人格约30秒。复杂周末场景因校验重试耗时158.11秒；不能据此声称实时已达秒级。已存用例可直接查看，实时重生成仍受模型网关、输出长度和校验重试影响。

所有候选、设定、操作与车机反馈均为虚构；这演示配置策略下大模型的选择，不是心理测量或真实车辆效果。

就餐展示记录由735d1b276aff4ec6ad2b441ffae11ac6的原始模型输出重新编译：仅补齐缺失的地点搜索，再通过原校验器；原失败完整链路与新校验方案一起保存，界面明确标记，不将本地重编译耗时冒充模型生成速度。

## 人格特征与依据图

每个人格结果下显示本轮保存的主导功能、行动原型，可展开画像与判断逻辑。差异框中的依据图按“共同输入 → 人格关注点 → 记录的取舍理由 → 动作”展示，支持切换动作查看并高亮。动作差异区分是否采用、参数及仅描述变化；不会对未采用动作补写未记录的心理理由。交互策略中相同的规则标作共同要求。解释数据直接从原运行审计读取，不使用修改后的当前配置替代历史配置，不增加模型调用。

## 全部差异清单与场景选择

首屏保留一项重点差异，同时新增全部对照清单：按动作采用、参数、仅描述筛选；准备查询与结果/控制分开标识。每行对照两边的具体值及其理由关联因素，点击后联动依据图。参数差异是字段差异，不等同于真实效果差异；不统计未保存的执行方式字段。

关联证据分为模型明确提及的配置策略/交互维度，以及根据理由用词找到的文本关联；后者只是查看线索。未启用维度、未采用动作、声明人格未改变的动作，不补造人格因素。共同规则单独标记；各分支自己的演示假设可展开查看。

用例优先级：就餐取舍（具体选择标准）→周末出游（行程组织与服务延伸）→下班休息（主动介入范围）。配置记录选择理由、观察点和已有单轮试跑现象，不预写下一轮人格答案。高速疲劳、快迟到等强约束场景不作为主展示。

## KEV 本地模型入口

`/demo/kev` 与 `/demo` 共用界面、三场景、差异高亮和配置依据图；顶部可切换模型并保留情境草稿。提交接口 `/api/persona-demo` 新增 `model: "kev"`，原请求省略该字段仍用原模型。KEV 记录保存模型标识，不复用原模型的已存示例；审计保留原始请求、概率、人格配置与编排结果。

依赖本地 `http://127.0.0.1:8009/v1/systemone` 的 Kev-0.8B。未启动时显示明确错误，不回退原规划器。沿用共享情境理解及 Step 3–6 配置；三个预设场景使用相同虚拟资源，KEV 判断候选、组织方式和是否追加动作。自由输入沿用原情境模型，再由原语言模型准备两种人格共用的中立候选，之后交给 KEV 选择，所以准备阶段可能较慢。

KEV 不是 Chat API 的直接替换：话术由程序组织，受限决策编译后经过原原子能力与依赖校验。独立因素判断不充当动作原因，不冒充模型内部推理或心理因果解释。各模型入口单独标注来源与实际总耗时。

### 情境原子能力采用概率实验

新运行逐项覆盖能力库：按共同情境标记为候选、必要前置、共同任务，或给出排除理由。三个预设场景当前覆盖潜在能力分别为24、25、22项，其中18、19、21项独立调用 KEV 的采用／不采用判断，其余前置与共同任务没有伪造概率。候选参数是两种人格共用的演示假设，不是用户历史偏好。

概率表保留每项原始采用概率与模型选项，绿色高亮最终模拟计划采用的动作。编译器补齐依赖、处理互斥动作时保留模型原分数并标注调整原因；不把模型建议等同于最终采用。动作清单继续通过原能力库和依赖校验。每行是独立二选一，概率不按列相加，也未经人格场景校准。

旧记录不补造新分数，需重新生成。原模型入口不改为此实验。审计增加 `atomic_scope`、`atomic_scores`、共同动作参数候选以及原始请求与响应。
